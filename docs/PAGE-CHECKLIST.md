Original requirements are mapped individually in [ORIGINAL-SPEC-RECONCILIATION.md](ORIGINAL-SPEC-RECONCILIATION.md), with the current page audit in [FULL-APPLICATION-AUDIT.md](FULL-APPLICATION-AUDIT.md).

## Explicitly unavailable production capabilities

These are boundaries of the agreed GitHub Pages architecture, not fake working controls:

- Server-enforced authentication/permissions and tenant isolation; public role switching remains a simulation.
- Durable database/file storage, immutable audit retention and cross-refresh fictional records.
- Real payments, tax submissions, payroll/holiday accrual or certification of safety/legal compliance.
- Email/push delivery, scheduled report delivery and automations running while the browser is closed.
- Live host telemetry, automated backups/restores and production deployment of the prepared self-hosted backend.
- Native-device/camera certification. QR labels open mobile asset links; browser-local file selection is supported.

Verification and release evidence belong in the final workflow PR and DEMO-COMPLETION.md. The earlier large viewport sweeps are historical evidence, not repeated release gates.
